1. Вариант 2 Жадный алгоритм для составления расписания
Задача: реализовать жадный алгоритм для распределения работ на машины с минимизацией времени завершения (makespan).

2. Анализ алгоритма по шагам

Шаг 1: Инициализация

machine_times = [0] * machines_count
schedule = [[] for _ in range(machines_count)]

· Создаем массив для отслеживания времени на каждой машине
· Создаем структуру для хранения расписания

Шаг 2: Сортировка работ

sorted_jobs = sorted([(duration, i) for i, duration in enumerate(jobs)], reverse=True)

· Создаем список кортежей (длительность, индекс работы)
· Сортируем в порядке убывания длительности
· Результат: [(9,7), (8,3), (7,1), (6,5), (5,0), (5,9), (4,6), (3,2), (2,4), (1,8)]

Шаг 3: Распределение работ

for duration, job_index in sorted_jobs:
    min_machine = min(range(machines_count), key=lambda i: machine_times[i])
    schedule[min_machine].append((job_index, duration))
    machine_times[min_machine] += duration

· Для каждой работы (начиная с самой длительной):
  · Находим машину с минимальным текущим временем
  · Назначаем работу на эту машину
  · Обновляем время завершения машины

Последовательность назначений:

1. Работа 7 (длительность 9) → Машина 0 (время: 9)
2. Работа 3 (длительность 8) → Машина 1 (время: 8)
3. Работа 1 (длительность 7) → Машина 2 (время: 7)
4. Работа 5 (длительность 6) → Машина 2 (время: 13)
5. Работа 0 (длительность 5) → Машина 1 (время: 13)
6. Работа 9 (длительность 5) → Машина 0 (время: 14)
7. Работа 6 (длительность 4) → Машина 1 (время: 17)
8. Работа 2 (длительность 3) → Машина 2 (время: 16)
9. Работа 4 (длительность 2) → Машина 2 (время: 18)
10. Работа 8 (длительность 1) → Машина 2 (время: 19)

3. Временная сложность

Временная сложность: O(n log n + n × m)

4. Пояснение временной сложности

Анализ сложности по шагам:

1. Сортировка работ:
   
   sorted_jobs = sorted([(duration, i) for i, duration in enumerate(jobs)], reverse=True)

   · Создание списка: O(n)
   · Сортировка: O(n log n)
3. Распределение работ:

   for duration, job_index in sorted_jobs:  # O(n) итераций
       min_machine = min(range(machines_count), key=lambda i: machine_times[i])  # O(m)
   
   · Внешний цикл: O(n) итераций
   · Поиск машины с минимальной загрузкой: O(m) на каждой итерации

Итоговая сложность: O(n log n + n × m)

Где:

· n - количество работ
· m - количество машин

В типичном случае, когда m значительно меньше n, сложность составляет O(n log n).

5. Ответ на контрольный вопрос

Определение коэффициента аппроксимации α для задачи минимизации:

Коэффициент аппроксимации α - это верхняя граница отношения стоимости решения, найденного приближенным алгоритмом, к стоимости оптимального решения для задачи минимизации.

Формальное определение:
Для задачи минимизации алгоритм имеет коэффициент аппроксимации α, если для всех экземпляров задачи выполняется:

C_approx ≤ α × C_optimal

где:

· C_approx - стоимость решения, найденного приближенным алгоритмом
· C_optimal - стоимость оптимального решения
· α ≥ 1

Что характеризует коэффициент аппроксимации:

1. Гарантию качества: α характеризует, насколько "плохим" может быть решение алгоритма по сравнению с оптимальным в худшем случае.
2. Эффективность алгоритма: Чем ближе α к 1, тем лучше алгоритм. Если α = 1, алгоритм находит оптимальное решение.
3. Теоретическую оценку: Для задачи составления расписания (makespan) жадный алгоритм LPT (Longest Processing Time first) имеет коэффициент аппроксимации 4/3 - 1/(3m), где m - количество машин.
4. Практическую полезность: Знание коэффициента аппроксимации позволяет оценить, насколько можно доверять решению алгоритма для конкретной задачи.
